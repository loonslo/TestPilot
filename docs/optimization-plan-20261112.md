# 2026-11-12 Web 任务流程优化

TestPilot 启动后打开网页。测试人员在页面内选择资料、确认范围、生成或导入用例、审核并执行，随后从批次查看结果或选择用例重跑。开发验收使用合成资料、合成 HTTP 服务和模型替身。

- 资料选择覆盖本机盘符。Git 根目录、提交与仓库内相对源码路径分别记录。文档可独立选择，不填写虚构的提交。浏览与文件读取保留会话、来源及敏感路径防护。源码发现仍以现有 Python/FastAPI 适配器为边界。
- Web 层调用现有任务服务。环境配置只保存账号对应的环境变量名。审核材料固定用例修订、环境和执行器，人工提交审批后才进入执行。编辑生成新修订，旧审批与执行证据保留。
- 生成和执行由后台工作线程处理，每个任务同时只接受一项变更。执行按批次落盘并可关联重跑的上一批，单条证据归属原批次。审批失效时重新审核，同审批下可对同一环境回归复跑。跨版本自动映射留待后续，版本更新可建立新任务。
- 用例生成只调用配置的模型一次，无工具权限。保留超时、字符与输出长度限制。模型费用和供应商额度由使用者管理，模型凭据从环境变量读取。
- 接口与用例附近展示来源和依据，批次旁展示请求、响应、断言与报告。原始技术材料仍可查阅。

验证覆盖正常执行、断言失败、未批准或旧修订拒绝执行、重复启动、指定用例重跑、历史批次报告与证据。


## 第一性原则与验收结论（2026-11-13）

初级测试工程师真正需要完成的工作是：确认接口与环境，知道测什么和为什么，审核生成结果并修正，执行选定用例，依据证据判断失败原因，再用历史批次做回归。启动方式、内部 JSON 文件和 CLI 命令不应成为这些步骤的前置知识。首次使用仍需配置可用模型与测试环境，不能把“开箱即用”解释为凭空获得账号、业务规则或服务。

来源追溯的必要价值只有三个：解释用例/预期来自哪条文档或规则，说明本批次使用哪个修订和环境，提供失败请求与响应以便复现。因此在用例和批次旁呈现这些信息；原始任务 JSON 等调试材料放入默认关闭的技术详情。保留证据链，减少日常操作负担。

模块边界：Web 负责输入、审核交互和后台作业状态；任务服务继续负责发现、修订、审批校验、HTTP 执行和确定性报告；批次持久化原审批与证据。修改用例需要新审批，历史批次不能随当前任务变化重算成另一份结果。线程中断不自动重放请求，恢复时将缺失证据明确标为未知。

本轮已实现上述本机任务闭环并用浏览器和自动化测试验证；最终结果见 acceptance.md。跨版本自动迁移与差异映射仍需后续设计，目前更新版本可建立新任务；不把“选择上一批重跑”冒充跨版本自动回归分析。
