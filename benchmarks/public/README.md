# benchmarks/public

Agent 可以读的全部内容。这里不放缺陷位置、真值、补丁或现有测试。

| 文件 | 内容 | 怎么来的 |
| --- | --- | --- |
| `openapi.json` | 约 10 个在范围内的操作及其请求模型 | `tools/build_public_spec.py` 从参考构建运行时导出的 `/openapi.json` 裁出 |
| `response-notes.json` | 响应包络、字段、枚举大小写、版本与归档约定 | 在参考构建上观察后手写：被测服务的 OpenAPI 没有描述任何响应体 |
| `rules.json` | 18 条规则，分三个流程：F1 同币种汇总、F2 归档约束、F3 账号隔离 | 手写；`source` 标明出自文档还是需要业主确认的参考实现 |

对原始导出做了三处改动：只保留 10 个操作；给每个操作换上稳定的短名（如 `ledger.summary`），原名留在 `x-source-operation-id`；删掉 422 响应，因为服务实际对校验错误返回 400 和自己的错误包络。被测项目仓库里提交的 `openapi.json` 是旧快照（51 个路径，运行时是 52 个），所以不用它。

规则里 `owner_confirm` 非空的条目，说明文档没有明确写出，内容取自参考实现；这 10 条已由被测项目的主人在 2026-10-15 确认（`confirmed_on`），可以作为评分依据。
